01 Where this came from

I kept typing the same five things.

Not domain knowledge — just method, re-supplied by hand every session:

  • Investigate before you change anything.
  • Reproduce it first — don’t guess at the cause.
  • Write the failing test before the fix.
  • You said it works. Show me the output.
  • That was one step, not the whole task. Keep going.

So I wrote it down: named blocks of work, each with its steps and a definition of done. Then, for my own amusement, I named them in Latin.

That turned out to be the part that mattered.

02 The thing I didn’t expect

“Fix” is the most crowded word in your repository.

Here is how I think about it. Everything an agent touches while it works on your code is a triangle — fix, check, test, build, commit, refactor, done. Thousands of them, in the diff, the log, the stack trace, the branch name and my own request. My request stays a triangle, and should: it is a programming task, and programming tasks are written in programming words — fix the null deref in the session handler, the migration test is failing. What must not be a triangle is the framework that governs that work — the names of its blocks and its boundaries. Name those in programming words too and they dissolve into the pile.

So make the framework names squares. The work stays triangles, my request stays triangles, and only the layer that governs them changes shape. That is the entire trick, and it costs nothing.

Concretely, this is how crowded a triangle gets. I ask for that null deref. Before my framework says a word, the agent has already met fix five times — the branch it checked out, eleven commits, a stale FIXME, two test names, and my own sentence. Then my framework arrives and says it a sixth time:

That is the whole observation. Everything below is me working out what follows from it.

My squares happen to be Latin. Emendatio for a repair, Restitutio for a broken build, Purgatio for an analyser alert. Half a joke that stuck — those words appear in no repository I have touched, and the model still knows what they mean. Three is a sample: my own set runs to eight kinds of work, each with its own words for the phases, the proofs and the ending.

03 How it sits around the work

A layer of words your code never says.

The framework doesn’t replace anything or sit inside your language. It wraps it. Inside the blocks, everything is ordinary — your files, your commands, your commit messages. The edges are made of vocabulary that can’t be confused with the contents.

I never type Latin at the agent. I say “the login endpoint 500s on an empty body.” The vocabulary lives inside the skill file, where only the agent reads it. What I get back is a transcript with visible seams.

04 Picking the words

It doesn’t have to be Latin. It does have to be disjoint.

The requirement is only that the name not collide with the material it governs. But you can miss in two directions, and the shapes make it obvious which is which.

Why Latin lands in the middle band is a guess, not a finding: rare in source code, abundant in training data, still transparent — emendatio already means correction, so the name carries weight before I define anything. But that is me explaining my own result after the fact. Old Norse, liturgical terms, climbing vocabulary, chess notation — anything with real meaning your repository has never had reason to write down should do the same job. If you try one, tell me what happened.
