00 The charge

Fix a red pipeline — the right way to fix it was already a rule.

The nightly CI on sara — the task manager itself — went red: two jobs, a formatting slip and three tests that failed only on Windows. Under the framework that is a single, named kind of work: Emendatio, the repair of a defect a test can catch. What follows is every step the agent actually took, in order, to the millisecond — read straight from sara’s own telemetry, not retold from memory.

Watch where the calls fall. The method is loud at the two ends of the work and silent through the middle — and the middle is where the bug was actually found and fixed.

That is recall doing its job: not always right, always cheap. It steered the agent off a dead end, which is the opposite of dampening it.

— The Silence no charge yet 08:57:45 → 09:01:59

4 min 13 s · no sara call

Everything that actually repaired the bug happened in here — and none of it appears in the timeline above or below. This is the reconstruction, from the shell history the method never saw.

  1. read

    Read the red run.

    Two jobs failing — Formatting, and Test (windows-latest). 446 passed, 3 failed.

  2. read

    Read the gate and its three failing tests.

    run_acceptance_gate in guide/mod.rs; each test writes a marker file through a shell command.

  3. reproduce

    Reproduce the mechanism by hand.

    sh -c "echo x >> C:\Users\…\marker" — sh reads the backslashes as escapes, so the file is never written. Not a line-ending bug at all.

  4. locate

    Locate every instance.

    Three test command builders — lines 1518, 1554, 1599 — each interpolating a native OS path into sh.

  5. mend

    Write the fix.

    A test-local sh_path() that forward-slashes the path before it reaches the shell; replace marker.display() in all three.

  6. prove

    Prove it locally.

    cargo fmt · cargo test → 455 passed, 0 failed · cargo clippy → clean.

Four minutes of reading, reproducing, deciding and mending — the creative core of the whole job — with nothing to answer to, because the charge that should have framed it did not exist yet. The method was not followed here. It was simply absent.

→ The point

The gap is not a failure of the method. It is the method in the wrong order.

Thirteen of the fourteen calls fall in two clusters ninety seconds apart. The four minutes between them were not un-methodical — they were un-recorded. The fix is not “call sara more.” It is two changes of order that cost nothing:

01

Declare before you repair.

Write the acceptance criteria first. Then the silent middle has something to steer toward instead of being reconstructed afterward.

02

Route the checks through sara verify.

You were going to run fmt, test and clippy anyway. Run them through the tool and the commands themselves become the record.

Do both and the same four minutes fill themselves. Nothing slows down; the work simply stops being invisible. That is the whole argument this page exists to make — and it is built out of a single real run, so you can check it against the timestamps rather than take my word for it.

* Every timestamp, duration and flag on this page comes from sara’s own usage telemetry (VictoriaLogs), for one real run on 2026‑09‑09. Nothing here is reconstructed except the six shaded steps inside The Silence — which is the point: those are the steps the telemetry could not see.
